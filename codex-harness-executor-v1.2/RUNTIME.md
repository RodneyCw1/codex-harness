# 运行器接口与实现边界

## 进程与权限

可信 Node.js 协调者进程持有配置、API Key 和控制目录。模型调用使用 `POST <base_url>/chat/completions`、非流式响应、标准 assistant/tool 消息链。模型仅获得 `read_file`、`search_code`、`apply_patch`、`run_check`、`submit_candidate`，没有 shell、approve、decide、任意 HTTP 或控制目录访问工具。

补丁必须绑定当前快照，按文本 unified diff 严格核对行号、上下文、行数和 EOF；拒绝二进制、超过 1MB 的文本补丁、混合换行格式自动改写、路径穿越、盘符、ADS、Windows 设备名、短路径别名、链接和 junction。范围规则支持精确文件、目录末尾 `/`、目录末尾 `/**` 和全部 `**`，不支持其他 glob。Windows 路径范围匹配忽略大小写。

项目命令使用冻结注册表的 argv，不拼接模型提供的 shell。由 CLI 帮助输出识别原生 `codex sandbox` 或兼容的 `codex sandbox windows` 形式，要求 permission-profile 和 elevated 后端。每个检查使用全新临时副本，只允许写该副本及其中的临时目录；验收文件只读，原项目和控制目录显式禁读写。旧 strict 默认断网；v1.2 显式 trusted_local + network:true 允许普通读取与直接联网，指定敏感目录仍禁读写。

`doctor` 对已存在的合成标记执行真实读取、写入、删除及 TCP 连接测试。任何边界失败都会阻止工作 AI 执行和独立验证。CLI 不创建无限制后门，也没有 `--unsafe`、`--skip-sandbox` 或生产用模拟适配器。供应商 CLI 必须支持配置的实际权限边界；执行器不改防火墙，测试结果见 VALIDATION。

Key 来自进程环境或明确的项目外私有环境文件。后者只解析 `NAME=value`，不执行命令、插值或脚本。子进程环境使用白名单，清除 Key、代理、预加载变量等；已知 Key 出现在模型正文时会阻止发送，持久化输出执行脱敏。环境变量值本身不写验证报告，只记录摘要。

## 命令与输出

除 `--help` 和 `--version`，所有命令均要求 `--config`。stdout 为一个 JSON 结果；stderr 为中文摘要及事件。退出码 0 表示命令完成，2 表示阻塞/参数错误。检查场景失败会体现在证据中，不能仅看 CLI 退出码判断功能通过。

| 命令 | 输入及结果 |
|---|---|
| init | 收集清单，创建 worktree 或副本及控制目录；中断复用同一工作区；已接入返回原事实 |
| doctor [--live] | 实测沙箱；--live 另外测试所选模型两次工具往返；两个结果分别报告 |
| baseline | 执行 purpose=baseline 命令；结果写 baseline-results.json |
| prepare --task | 接收 Codex 草稿，冻结三份文档、上下文、保护文件、命令、AC/TC 映射；返回 1.0 任务路径 |
| run --task [--executor] | 只执行一轮并提交候选，或冻结 FINAL 候选；不自行审批 |
| verify --run | 对冻结候选新建检查副本，独立运行全部登记 TC，形成不可替代自测的证据 |
| inspect --run | 返回规范、差异、证据和日志预览；不修改状态 |
| decide --run --review [--rework] [--resolved] | 仅协调者提交评审，校验绑定关系、全部必需项、真实产物和当前版本 |
| status [--run] | 读取状态、当前阶段、暂停原因及计数 |
| stop --run | 写停止请求；运行器中止 HTTP 和检查子进程树 |
| cancel --run --reason | 取消已停止的未审批轮以便修订需求，保留代码、证据和计数 |
| resume --run [--new-batch] | 清理已确认死亡进程的锁，核对写操作和版本后恢复 |
| export --run | 仅最终 ACCEPT 可导出；差异、完整候选、规范、历史评审和验证证据 |

任务文件路径相对 control_root，draft/review/rework 参数是当前文件系统中的路径。引用文档与证据使用控制目录相对路径，不能引用 `..` 或任意外部文件。

`--resolved` 是可选的协调者辅助文件，内容是 `[{"defect_id":"BUG-001","evidence_ids":["evidence-..."],"explanation":"已核对实际修复与复验"}]`。必须引用前轮返工单及本轮成功的所有相应复验测试，用于表示“某个已验证阻断缺陷已解决，但功能的其他项仍需返工”。工作 AI 不可提供审批来源；单纯从新返工单删除旧缺陷不算进展。

## 配置与协议版本

配置 schema_version 是 **1.2**，兼容 **1.0/1.1**；可信本机模式必须显式启用。任务、执行报告、证据、review 和 rework 仍使用 `protocol_version: '1.0'`，由原有 JSON Schema 校验。内部 db.json 是运行器存储格式，不冒充旧版演示 run-state.json。固定协议原包在项目规范模板的 docs/harness/protocol-v1/ 保留。

快照摘要为按相对路径排序的文件条目列表（路径、原始字节 SHA-256、大小、可执行位）的规范 JSON 加换行后 SHA-256。排除项独立保存，默认不包含凭据、Git 元数据、依赖及构建产物。代码再次变化会使旧候选证据失效。规范摘要还绑定文档内容摘要、AC/TC、命令、范围及受保护文件。命令环境和配置摘要另外绑定到运行及检查报告。

## 验收语义

命令退出码零产生 `result: unverified`，由 Codex 检查实际断言和用户场景后将 review 项标记 pass。执行器验证每个 pass 项包含当前候选全部对应 TC 的成功执行记录以及必需产物，但不能替代 Codex 判断业务需求。非零退出码或环境错误不能通过。

log/report 自动收集；其他产物由 `project.artifacts.<command_id>` 声明，路径相对检查副本。例如截图类型 screenshot，测试报告类型 report。产物大小限制 20MB，复制前检查路径和链接；必需产物缺失会拒绝 ACCEPT。原始日志保留，inspect 只给有限预览。

规范、命令和执行者配置变更后不得混用证据。派发前修改规范增加 spec_version；运行中出现配置漂移时先恢复冻结配置，或 stop 后由协调者 cancel 当前未审批轮、修订规范再派发，不能静默替换供应商继续旧轮次。

## 状态、恢复和交付

db.json 原子替换，并在写前校验 revision。所有状态变更使用单写入锁，事件追加到 events.jsonl；状态事务先写 transaction.json，生成独立 transactions 记录，再原子提交 db.json 与追加事件索引；中断后在互斥锁内按版本和摘要补齐。未完成事务不能被当作功能已通过。

补丁先在控制目录暂存副本验证全部文件，持久化前后快照和操作意图后才写工作区。恢复时每个变更文件必须匹配写前或写后值；属于已记录部分写入的文件补齐到目标快照，已完成的工具 ID 返回原结果，内容冲突阻塞。被中断的检查在新临时副本重新运行，旧检查产物不冒充新验证。

首次提交计一轮，每功能每批次最多 10 轮；重复候选/评审不会再计数。第 10 轮仍可 ACCEPT。无新增必需通过项、无已证实阻断缺陷关闭，或发生验收项回退，均不算进展；连续 3 轮无进展暂停。普通恢复保留计数，明确续跑预算暂停的 `--new-batch` 才创建新批次，累计历史保留。

临时网络、429 和 5xx 最多额外重试 3 次，退避 1/2/4 秒或有界 Retry-After；认证/协议错误不重试。默认请求 120 秒、单个命令 600 秒（配置上限 3600 秒）、一次工作 AI 执行 1800 秒、100 次工具调用。上下文超过配置上限会阻塞，交由 Codex 缩小任务，不丢弃既有约束继续猜测。

导出生成 changes.patch 和 before/after 快照；补丁基线包含接入时的未提交改动，合并前需与用户当前现场比较。不会自动清理工作区、证据或 worktree；有意保留以便恢复。生命周期清理应由协调者确认交付后另行进行，不提供隐式递归删除。

## 已知边界

- 首版生产运行仅支持 Windows + Node.js 24；多执行者只做选择，不做并行或自动故障切换。
- CLI 生命周期由当前 Codex 会话调度，关闭会话不会有后台决策模型持续运行。
- 未集成桌面 GUI/MCP 服务；Codex 通过这些命令和 COORDINATOR.md 完成循环。
- 控制目录依赖宿主用户与 OS 沙箱的隔离。与协调者同一宿主身份的恶意进程不在本版威胁模型内。
- read_roots 是可信运行时/缓存；预检通过不构成形式化安全证明。真实项目、供应商和网络白名单仍须在目标环境复测。
