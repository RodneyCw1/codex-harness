# Codex 评审表

先检查验收文档的硬门槛。任何必需项未验证、失败、证据不可信或存在阻断缺陷，都不能ACCEPT。

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 正确性 | 必需行为失败/未验证 | 主路径成立但存在未解决必需项 | 必需行为及边界全部有证据 |
| 验证 | 仅执行者声明或证据缺失 | 部分检查真实执行 | 当前候选所有必需检查真实完成 |
| 范围纪律 | 越界或改写标准 | 范围变化说明不足 | 范围明确、变化可追溯 |
| 可靠性 | 无法复现/恢复 | 可运行但恢复说明有缺口 | 启动、重跑、恢复路径明确且有适用验证 |
| 可维护性 | 违反项目约束或严重难懂 | 有非阻断改进项 | 符合项目惯例，接口及意图清晰 |
| 交接准备 | 只有聊天信息 | 部分状态或命令缺失 | 文件和证据足够下一会话接手 |

评分用于解释质量和校准评审，不以总分或平均分替代硬门槛。非阻断建议不得无限扩大任务范围。

校准做法：用项目已知通过和已知失败案例对照人工判断，记录误放行/误拒绝及规则修订，重新评审相同案例。正式使用前至少覆盖本包的异常场景。不要为了与执行者的自评分对齐而放宽标准。
