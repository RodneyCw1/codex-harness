## Codex Harness 工作流

本项目采用 Codex 决策、外部 AI 执行、Codex 独立验收的工作流。完整规范位于 `[本项目工作流文档路径]`，项目画像位于 `[项目画像路径]`，当前任务状态入口位于 `[状态入口路径]`。

### 开工

1. 读取有效项目指令、项目画像、当前进度和交接。
2. 核实工作区、基线、规范版本及未提交改动；不覆盖用户现场。
3. 存在 `.codegraph/` 时优先用 CodeGraph 理解代码；否则常规搜索。
4. 按项目配置运行初始化和基础验证；确认外部执行器及模型能力。
5. 由 Codex 冻结实现、验收、测试文档，并建立 REQ → AC → TC 关系。

### 工作规则

- 同时只推进一个功能；依赖通过后才能派发。
- 执行者只能修改任务范围内的实现和允许的测试，不改验收标准、官方证据或权威状态。
- 自测报告触发验收，不代表通过。Codex 必须审查真实差异并独立验证。
- 每功能每批次最多 10 次提交，连续 3 轮无进展暂停；不自动重置批次。
- 预授权范围内自动执行、验收和返工；宿主权限仍然有效。

### 完成与收尾

- 所有必需验收项和检查通过，证据与当前快照和规范一致，无阻断缺陷。
- 整体交付还须在最终快照通过规定的集成和回归。
- 更新真实状态、进度、交接和证据；暂停不能标记完成。
- 交付待合并成果，不自动合并或发布。
