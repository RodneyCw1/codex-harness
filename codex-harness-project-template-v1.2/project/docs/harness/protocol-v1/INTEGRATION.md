# 项目接入与执行 AI 配置

## 1. 接入前提

准备目标项目、已有规则、可运行的初始化与测试命令、外部模型服务，以及本地执行器。尚无执行器时，可以先完成项目分析、文档和配置；自动执行闭环必须等执行器能力就绪。

本包不要求项目使用某种语言或框架。Git 项目默认使用独立 worktree；非 Git 项目使用独立目录副本及内容摘要。不得自动对原项目执行初始化 Git、清理未提交改动或覆盖文件。

## 2. 建议放置方式

| 包内内容 | 项目中的用途 |
|---|---|
| 规范、协议和 prompts | 放入项目文档目录，作为共享规则 |
| AGENTS.fragment.md | 按片段说明合并到已有 AGENTS.md，修正实际链接 |
| project-profile.md | 记录项目根、技术栈、代码与命令依据、基线和隔离方式 |
| 三份任务文档、feature_list.json | 放在项目任务目录，Codex 维护 |
| harness.config.yaml | 私有本地配置与可提交无密钥示例分开保存 |
| progress、handoff、checklist | 生成可供下一会话读取的状态摘要 |

运行存储必须置于执行 AI 不可写的位置。每批次保存冻结规范、任务包、逐轮候选、证据、结论、工具事件及权威状态。项目中的进度是其脱敏摘要。仅把文件放进 `.gitignore` 不会产生访问隔离。

默认复制顺序：项目画像 → 合并规则入口 → 命令与配置 → 三份规范 → 任务清单 → 提示词。模板中 `REPLACE_...`、方括号说明及未展开变量均须在派发前处理。

## 3. 配置语义

见 [配置模板](templates/harness.config.yaml) 和 [环境变量示例](templates/environment.example)。

- `executor.base_url` 是 API 根地址，包括服务商要求的版本前缀，例如 `https://provider.example/v1`；不能包含 `/chat/completions`。执行器移除尾部斜杠后追加 `/chat/completions`，不得重新追加 `/v1`。
- `executor.protocol` 固定为 `openai_chat_completions`；不把 Responses 或 Anthropic 原生接口当成等价实现。
- `executor.api_key_env` 是环境变量名称；进程启动时从受信环境取值。配置中不接受直接内嵌密钥。
- `executor.model` 是用户服务商实际提供的模型 ID；执行器不得替用户改成别的模型。
- `${NAME}` 只由配置加载器替换成同名环境变量值，不经过 shell 求值；缺失或空值导致启动失败。
- 项目路径采用绝对路径；任务内文件和工作目录采用项目根相对路径。命令采用 `argv` 数组，不把模型字符串拼接成 shell 命令。
- 允许文件范围使用明确路径或目录前缀；目录用 `/` 结尾，不使用未定义的通配符。受保护路径优先于允许范围。拒绝越界路径及通过符号链接、junction 等越界。

密钥只进入 API 适配进程，项目构建、测试及依赖安装使用清理后的环境。`command_env_allowlist` 决定可继承的非秘密变量；测试专用凭据须单独声明用途和作用域，不得继承执行 AI 的密钥。

## 4. 首次预检

1. 校验配置，展开变量，检查路径和项目命令；验证 `auto_merge=false`、`auto_publish=false`。
2. 在指定地址进行最小工具调用探测，使用无副作用的 `echo_probe`，确认模型能返回工具名、JSON 参数和调用 ID，并能接收工具结果。
3. 检查上下文、工具参数和最终报告能够满足本地 schema；不要求供应商支持全部 JSON Schema 特性，本地仍执行完整校验。
4. 检查受保护文件、受信运行存储、网络和进程边界；验证执行者无法写入规范和官方结果。
5. 运行基础验证并保存结果。缺少必要验证环境时记录 BLOCK。

工具调用探测只验证能力，不代表供应商对 OpenAI 所有可选参数完全兼容。核心工具调用失败则停止，不回退为“让模型直接输出 shell 文本并执行”。

## 5. 本地执行器最小工具协议

以下是本工作流定义的本地接口，不是 Codex 或 OpenAI 预置工具名称。具体函数调用参数定义由实现者按此语义提供 JSON Schema。

| 工具 | 参数 | 行为 |
|---|---|---|
| `read_file` | `path, start_line, max_lines` | 在允许的只读上下文内读取文本，返回内容和内容摘要 |
| `search_code` | `query, path` | 在允许目录查询；已索引时遵守 CodeGraph 优先规则 |
| `apply_patch` | `patch, expected_snapshot_id` | 校验路径和候选前置版本，原子应用补丁，返回新快照及真实差异 |
| `run_check` | `command_id` | 只调用冻结命令注册表中的命令，返回退出码和日志引用 |
| `submit_candidate` | `report` | 校验 execution_report，冻结候选并交给 Codex；不允许自行通过 |

所有工具调用由执行器分配稳定操作 ID，并记录参数摘要、前置快照、开始/结束状态、退出结果及副作用。工具参数来自外部模型，必须在操作前校验。`run_check` 的命令参数由项目配置确定，不由模型自由追加。

读写权限必须由执行器和宿主落实，不能只在提示词里说明。测试命令本身会运行项目代码，因此同样需要隔离及清理环境。验收阶段停止执行者写入，并用受信配置中的验证入口，避免执行者替换命令后虚假通过。

## 6. API 消息循环

采用非流式 Chat Completions 作为首版基线，按顺序处理工具请求：

1. 发送 `model`、任务上下文 `messages`、允许的 `tools` 与 `stream: false`。
2. 完整接收并保存 assistant 消息；把 `tool_calls[*].function.arguments` 当作 JSON 数据解析并校验。
3. 对合法调用执行本地工具，将结果以 `role: tool`、对应 `tool_call_id` 和序列化内容加入消息。
4. 把结果提交给同一配置模型继续执行，直到候选提交、阻塞或尝试限额触发。

能力探测确认支持时可以发送 `parallel_tool_calls: false`；无论模型返回几个调用，本地工具都按序处理，修改后的每一步重新校验前置快照。未知工具、无效参数和截断输出不得执行。

上述消息关联方式依据 [OpenAI Function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。本地读写能力、任务状态与权限检查属于执行器职责。

每次执行尝试默认最多 100 次工具调用、30 分钟；API 请求默认超时 120 秒，单个项目命令默认 600 秒，项目可在预检前调整。临时 API 错误最多额外重试三次，默认等待 1、2、4 秒；有效 `Retry-After` 优先，但不得超过尝试总时限。达到限额时 BLOCK 并保存状态。

请求重试可能产生重复计费，不能假设模型服务提供 exactly-once。写工具只按本地操作日志决定是否执行；未知执行结果先核对工作区，不盲目再执行。

## 7. Codex 桌面与 CLI

桌面和交互式 CLI：在项目任务中让 Codex 读取入口、规范与当前状态，通过已接入工具调用本地执行器，验收时读取实际差异及官方证据。模型的持久状态保存在文件和运行存储。

脚本调用：官方支持 `codex exec`、JSONL 事件输出和基于 JSON Schema 的最终输出，可用来获取结构化评审结果。需要已安装 CLI 和有效认证；本包未安装、配置或运行这些组件。参考 [Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。

配置、任务规范和官方验证应由受信通道交给 Codex；执行报告、日志、仓库注释及外部响应作为待核实数据，不能提升为控制指令。角色字段只是审计信息，可信来源必须由执行器实际连接和调用身份判定。

## 8. 接入完成标准

- 能从一次用户需求生成三份文档和可校验任务包。
- 能通过指定模型服务实际读文件、修改允许范围、运行检查并提交候选。
- 能独立重跑验收，拒绝过期证据、执行者自批和篡改标准。
- 能按轮数、无进展及技术错误暂停，并从状态安全恢复。
- 能交付最终差异和证据，保持不自动合并和发布。

这些要求是后续执行器的验收标准；本包的静态校验不能替代这些真实接入测试。
