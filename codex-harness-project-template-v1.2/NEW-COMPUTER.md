# 新电脑使用 v1.2

保留两个压缩包：执行器包解压到项目外的工具目录；规范模板包先解压到临时目录，让 Codex 依 CODEX-SETUP.md 合并进项目。不要整包覆盖已有规范。

还需要 Node.js24、Windows Codex CLI 及已设置的 elevated 沙箱；Git 项目需 Git，项目自身运行时按实际代码安装。执行器已编译，无需自行 npm install 或构建。

在目标项目的 Codex 会话发送：

> 项目路径：<项目>；规范模板目录：<模板目录>；执行器目录：<工具目录>。请按 CODEX-SETUP.md 完成接入、分析项目、生成项目外配置和启动入口、预检与基线；我的需求是：<需求，或本次只接入>。

API 地址与模型写入项目外 YAML 的 executors；Key 写 private_env_file 指向的项目外私有文件，格式 WORK_AI_PRIMARY_KEY=实际值，不发到聊天。可以配置多个执行者，每次只选择一个，不自动换模型。

本模板显式采用可信本机模式 trusted_local + network:true，允许普通文件读取与联网，指定敏感路径仍拒绝访问，写入限检查副本。适用于你信任的项目代码，不承诺全面读取隔离和断网，也不修改防火墙。旧配置不会因升级自动切换模式。

文档保存在项目 docs/harness；本机配置、Key、独立工作树和控制状态保存在项目外。日常由当前 Codex 会话调度，无第二个决策模型 API，无后台常驻服务，无需逐轮传递 JSON。全部功能还须最终回归，成果不自动合并或发布。

换电脑重新绑定实际路径和运行时；没有完整 control/work 记录时不能宣称恢复旧运行。新电脑重新 doctor --live，测试机通过不代表所有项目已通过。
